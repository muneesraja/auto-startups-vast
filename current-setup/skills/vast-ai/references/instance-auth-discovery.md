# Vast.ai Instance Auth Discovery

**When to use this:** User says "get me the password", "get the ComfyUI token", "what's the auth for the instance", or asks for credentials needed behind a Cloudflare tunnel. **The token in the Vast portal is the same one for the ComfyUI API via the tunnel.**

## Quick facts (memorize)

| Field | Value |
|---|---|
| **Username (Basic Auth)** | `vastai` (from `WEB_USERNAME` env, default in `caddy_config_manager.py`) |
| **Token / password** | The value of `$OPEN_BUTTON_TOKEN` env var (also stored as `$JUPYTER_TOKEN` on the same instance) |
| **Token use** | Query string `?token=...`, `Authorization: Bearer *** header, **or** `Cookie: C.<instance_id>_auth_token=...` |
| **Where it lives on disk** | Plaintext in `/etc/Caddyfile`, hashed (bcrypt) in the `basic_auth` block of the same file |

## The "open button" port layout

Vast's ComfyUI template (`vastai/comfy:v0.23.0-cuda-13.2-py312` and similar) runs a Caddy portal stack on internal port **1111** that reverse-proxies to ComfyUI on **18188**. That portal is what Cloudflare tunnels expose to the internet.

The Caddy config at `/etc/Caddyfile` has the token **in plaintext** in the CEL expressions for the three auth paths:

```caddy
(token_auth_matcher) {
    @token_auth {
        expression `{http.request.uri.query.token} == "7e6009b49e7d..."`
    }
}
(has_valid_auth_cookie_matcher) {
    @has_valid_auth_cookie {
        expression `{http.request.header.Cookie}.contains("C.40688048_auth_token=7e6009b49e7d...")`
    }
}
(has_valid_bearer_token_matcher) {
    @has_valid_bearer_token {
        expression `{http.request.header.Authorization} == "Bearer 7e6009b49e7d..."`
    }
}
```

The Basic Auth fallback uses bcrypt:
```caddy
route {
    basic_auth {
        vastai "$2a$14$0Akw2DFixBXjJsj9ZnsYkuBFi1sSPqccXimk.hDNMV9N17cI1O8f6"
    }
    ...
}
```

The bcrypt hash is computed from the **same** plaintext token (see `generate_auth_config` in `caddy_config_manager.py` — it calls `caddy hash-password -p <password>`). So Basic Auth `vastai:<token>` works the same as the Bearer/query/cookie forms.

## How to extract the token from a running instance

```bash
# SSH in (use the alias you set up, e.g. mandi-flux2)
ssh mandi-flux2

# 1. Confirm token from env (canonical source)
env | grep -E "(OPEN_BUTTON_TOKEN|JUPYTER_TOKEN)"

# 2. Extract plaintext token from the live Caddy config (regex over /etc/Caddyfile)
grep -oE '"[a-f0-9]{20,}"' /etc/Caddyfile | head -1 | tr -d '"'

# 3. Confirm username (defaults to "vastai")
grep "WEB_USERNAME" /etc/portal-aio/caddy_manager/caddy_config_manager.py
# → web_username = os.environ.get('WEB_USERNAME', 'vastai')
```

The token is **auto-generated by `shortuuid.uuid()`** if neither `WEB_PASSWORD` nor `OPEN_BUTTON_TOKEN` is set at boot. Either way, after boot it's frozen in `/etc/Caddyfile`.

## How to use the token behind a Cloudflare tunnel

Once a tunnel is set up to the Vast box (e.g. `https://comfy-mandi.muneesraja.com → localhost:1111`), any of these work:

```bash
# Easiest: query string (browser, curl, no header needed)
curl "https://<tunnel>/system_stats?token=7e6009b49e7d...a20"

# Bearer header (for API clients / scripts)
curl -H "Authorization: Bearer 7e6009b49e7d...a20" https://<tunnel>/system_stats

# Basic Auth (browser popup, curl --user)
curl -u "vastai:7e6009b49e7d...a20" https://<tunnel>/system_stats
```

## Storing the token safely

**Never hardcode the token.** Always use `$COMFYUI_AUTH` env var in the format `<username>:<token>`:

```bash
# In the LXC's root .env (used by eval pipeline, kanban workers, etc.)
export COMFYUI_AUTH="vastai:7e6009b49e7d7289ba06c30a06c5879083bf97c3892518a075b3aab33d224a20"
```

Then any client can do:
```python
import os, base64, requests
auth = base64.b64encode(os.environ["COMFYUI_AUTH"].encode()).decode()
requests.get("https://<tunnel>/system_stats", headers={"Authorization": f"Basic {auth}"})
```

## Why the user is asking

Munees exposes Vast ComfyUI behind a **Cloudflare tunnel** (not a Vast-proxied URL — those leak the host's IP). The tunnel needs a username + password for the auth layer in front of Caddy. The "password" is just `$OPEN_BUTTON_TOKEN`. This is the same auth the Vast "open button" uses when you click the portal link in cloud.vast.ai — the tunnel just exposes that same endpoint to a public URL.

## Rotating the token (if compromised)

There's no Vast API to rotate this. You have to **destroy the instance and re-provision**. (Alternatively, edit `/etc/Caddyfile`, regenerate the bcrypt hash with `caddy hash-password`, and reload caddy — but the next Caddy config-manager restart will regenerate it from env, so the only durable fix is a new instance.)
